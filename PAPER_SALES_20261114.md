# Paper-signed sale recording

Implemented a separate, immutable paper-sale source. Owners and administrators can record an already paper-signed sale for an available car or the matching reserved deal. The two steps are review and explicit confirmation. A new buyer needs a name and buyer type; email/phone are optional. An existing deal keeps its existing buyer. The agreed gross price, paper signing date, reference and original-document note are mandatory.

Confirmation atomically creates the buyer/deal when necessary, stores the immutable reviewed buyer/vehicle/price/date snapshot and actor, completes the deal, releases its reservation, and marks the car sold. It creates no electronic signature, signing PDF, email, payment entry or assertion of bank verification. Existing signed documents remain intact. The paper reference identifies the externally held original; it is not a digital signature.

Fresh approved-account, active-company and selected-company checks apply in the action and database layers. Finance can read; sales/viewer cannot use this flow. Direct private-table access is revoked. Exact request replay returns the same review/receipt. Altered nonce payloads, another reservation, archived/cancelled/completed deals, mismatched customer/deal/stock, electronic contract sources, existing financial settlement and stale reviewed stock/customer/reservation data are rejected. Locks follow existing inventory lifecycle ordering: identity/company scope, stock, deal, customer and reservation mutation.

The optional archive helper is checked dynamically so migrations can be applied in lexical order. Install all three current feature migrations before exposing the integrated UI. Parent-owned inventory/deal entrypoints use `PaperSaleForm`; the component accepts `onBusyChange`, `onAccessDenied` and `onCompleted`. A lost result preserves the exact request and blocks navigation until explicit replay resolves it.
